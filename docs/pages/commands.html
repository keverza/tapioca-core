Command authoring

Describe the workflow. Let the palette handle the edges.

A Tapioca command is a top-level run function plus literal metadata that the palette can read without executing the command.

The smallest useful shape

One folder. One entry file. One clear question.

Production commands live under the command roots and are copied to the managed command directory by the sync script. Do not edit the deployed copy directly.

Authoring rules

Keep the scanner and the user on the same page.

The palette reads metadata before it runs Python.

01

Use the public import

New commands should use import tapioca. Existing import evp commands remain valid.

02

Keep metadata literal

Decorator and annotation values read by the scanner must be AST-readable literals. Computed metadata can disappear from the palette.

03

Keep UI in the host

Use tapioca.ui for results and controls. Do not create tkinter, Qt, or another Python UI.

04

Respect selection state

Declare needs_selection=True when the command needs the active selection so the palette can enforce that precondition.

05

Batch writes

Destructive workflows should default to a dry run and use one transaction for real writes, giving the user one undo step.

06

Check cancellation

Long pure-Python loops should call tapioca.runtime.check_cancel() between chunks.
