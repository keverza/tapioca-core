# PEP 8 — Enforce Python Formatting and Linting for the EvP Add-On

Apply one repository-root `ruff` configuration to the active Python sources in the
EvP tree. New and touched `.py` files are formatted to PEP 8 and linted for common
bugs without making an unfinished whole-tree conversion a blocking gate.

**Related:** `historical source docs/archicad-quality-pipeline.md` (the broader CI/quality plan
that already references ruff, mypy, and vulture — this task is the concrete
first step that turns that plan into reality), `AGENTS.md`, and `CLAUDE.md` (the
always-loaded Python style policy).

## Current Repository Policy

The active Ruff configuration lives in the repository-root `pyproject.toml`; there is
no second `AddOn/EvP/pyproject.toml`. `tools/quality/check_python.py` scans the command
roots and checks only explicit or staged Python files. The versioned hook at
`AddOn/EvP/.githooks/pre-commit` uses that runner, so legacy files do not block an
unrelated change. Enable it once with `git config core.hooksPath AddOn/EvP/.githooks`.

Before any Ruff autofix over command folders, capture the scanner output with
`python tools/quality/check_python.py --scan-only --json` and compare it byte-for-byte
afterward. A changed metadata file means the autofix changed what the palette can read.

The standalone script folders and archived probes remain outside the active cleanup
scope. Whole-tree formatting is an optional cleanup pass, not a prerequisite for
feature work.

## Ruff Configuration

Ruff is chosen because it replaces flake8, isort, and black in a single tool,
matches the tool already cited in `historical source docs/archicad-quality-pipeline.md`, and
runs at C speed (relevant for a 200-file tree).

The repository-root `pyproject.toml` contains the active configuration:

```toml
[tool.ruff]
target-version = "py312"
line-length = 120

[tool.ruff.lint]
select = [
    "E",      # pycodestyle errors
    "W",      # pycodestyle warnings
    "F",      # pyflakes (unused imports, undefined names, etc.)
    "I",      # isort (import sorting)
    "B",      # flake8-bugbear (common bugs)
    "RUF100", # unused noqa
]

[tool.ruff.lint.isort]
known-first-party = ["evp", "tapioca"]

[tool.ruff.format]
quote-style = "double"
indent-style = "space"
docstring-code-format = true
```

Key decisions:
- **`line-length = 120`** — matches the C++ `ColumnLimit: 120` in `AddOn/clang-format`. Keeps the whole codebase consistent and avoids forcing short-line PEP 8 dogma on code that legitimately uses long ACAPI GUID strings and nested dict literals.
- **`quote-style = "double"`** — matches the existing codebase convention. A scan of `Sources/PyPackage/evp/` shows `"` quotes dominate.
- **`indent-style = "space"`** — PEP 8 default. The C++ side uses tabs; Python follows its own idiom.
- **`I` (isort)** — auto-sorts imports. Commands import `evp.*`, `tapioca.*`, `json`, `math` etc. consistently.
- **`B` (bugbear)** — catches real bugs (mutable defaults, bare excepts, etc.) that have caused Archicad crashes before.

## Implementation Path

### Phase 1 — Configuration and runner (landed)

1. Install Ruff from `dev-requirements.txt` in the development environment.

2. Use the root `pyproject.toml`; do not create a second add-on-local config.

3. Run the staged or explicit-file checker:
   ```bash
   python tools/quality/check_python.py --no-scan <path/to/file.py>
   ```

4. Enable the versioned hook once per clone:
   ```bash
   git config core.hooksPath AddOn/EvP/.githooks
   ```

**Done-state check:** the command scanner passes and Ruff format/lint pass on the
explicit or staged Python files.

### Phase 2 — Optional cleanup pass

Whole-tree formatting and lint cleanup is a dedicated pass, not a prerequisite for
feature work. Before any autofix over command folders:
   ```bash
   python tools/quality/check_python.py --scan-only --json > scan-before.json
   ```
   ruff format <files>
   ruff check --fix <files>
   python tools/quality/check_python.py --scan-only --json > scan-after.json
   ```
   The two scanner files must be identical apart from intentional source changes.

### Phase 3 — Enforcement (prevent drift)

The versioned hook at `AddOn/EvP/.githooks/pre-commit` resolves a repository-local
virtualenv first, falls back to `python`, and warns rather than blocks when Python or
Ruff is unavailable. It delegates staged-file selection to `check_python.py`.

An optional CMake target may be added later for CI, but it must follow the same
touched-file policy rather than making the unfinished whole-tree conversion a C++
build gate. The versioned hook is the current enforcement mechanism.

## ⚠️ Caveats

### `_scanner.py` may need care

`AddOn/EvP/Sources/PyPackage/evp/_scanner.py` does AST parsing of command files.
Ruff should not change its logic, but import sorting might reorder `from __future__`
or `from typing import` statements. Verify the scanner still parses all commands
after reformatting. If ruff breaks the scanner, exclude `_scanner.py` from isort
with a per-file override.

### Whitespace reformatting is a merge-conflict generator

Do not reformat the whole tree as a prerequisite for feature work. Format a file as
it is touched, or schedule a separate cleanup commit when the tree is quiet. This
keeps style adoption reviewable and avoids conflicts with concurrent Python changes.

### Archived probe commands

Files under `historical source probes/2026/` are deactivated commands and frozen evidence.
They are outside the active command root, so the scanner and sync never see them;
pytest excludes the structured `historical source ` root as well. Do not edit them in place.

### Ruff installation is machine-local

Ruff is listed in `dev-requirements.txt` and is not committed into the repository.
The hook checks a repository virtualenv first and then the system `python`; a missing
tool produces a warning and does not block an unrelated commit.
